# ARC-M6-23: remove every tag and caption badge from the UI

- Owner: frontend engineer. Tier B (UI copy and tests), but it deletes many test assertions, so the orchestrator checks the test diff line by line.
- Asked by: Om, 2026-11-27: "we also need to remove all these from the UI: Draft, not confirmed / Missing / Newest first / Live / Sample, not approved ... identify such texts and remove all of them. IT IS A LIVE PRODUCT NOW". Asked which kinds, Om chose all three: status and caption tags, source labels on numbers, and working markers.
- Depends on: ARC-M6-22.

## Remove
1. Every rendered chip: all uses of `Chip`, `ProvenanceChip` and `LabelChip` in `web/src` (including Planning's local `LabelChip`, the Arc answer chips in `components/arc/AnswerView.tsx`, `Changed`, `Done`, `Held`, `Needs you`, `Partly done`, `Approved`, `Draft, not approved`, `Draft, not confirmed`, `Sample, not approved`, `Missing`, `Not connected`, `Model estimate`, `Model estimate, predicted`, `Modelled on our plant`, `Modeled records`, `Generated by Gemini`, `Entered by operator`, `Confirmed by operator`, `From order`, `From catalog`, `Weather record`, `Approved sample`, `Sample`, `Read`, `Not read`, `Kept on this page`, `Reads the file once`, `Example image, not the approved photo`, `Empty until lot history is connected`, `Future`, `Roadmap`, `Replaced, read only`, `Not current`, `Insufficient data`, `Out of scope`, `Uploaded photo`, `Approved reference photo`, the Planning stage and capability labels). Then delete the chip components, the `PROVENANCE` map and their styles if nothing uses them.
2. Status pills that are tags rather than sentences: the Home lots `Live` and its sibling states (`web/src/pages/home/Lots.tsx` around line 158), the job-card corner tag on Home, and any `.pv` span.
3. Caption badges and disclaimers beside titles: `meta="Newest first"`, "Illustration. Not real results.", "Example lot. Nothing here is from your plant.", "Software steps, not a factory network.", "Modeled lots", "Selected lot, percentage points" stays only if it is an axis unit (keep units), the Arc footer "Answers use sample data until sensors are connected.", and the sentence "Sensor readings are not connected yet." (keep "Type what you see on the floor.").
4. The Arc receipt row "Card checked / Not connected".

## Keep
- Sentences that tell the user what failed or what to do (error and empty-state messages, for example "The impact summary could not be read..."). If a `NotConnected` card loses its chip, its message stays.
- Units, axis titles, field labels, buttons, headings, the step icons and their legend, and the entered-to-proposed values (the arrow still shows what changed).
- Accessible names: where a removed chip carried meaning for screen readers (for example a changed setting), keep it as visually hidden text or an `aria-label`, so the page still reads correctly.
- Server code, the Arc answer label lists, the evals and the job-card PDF are not part of this ticket.

## Acceptance criteria
- None of the texts listed above renders on any `/app` page or in the Arc panel (browser check over every route and the Arc lot flow).
- No unused component, style, import or type is left behind (`npx tsc --noEmit`, build).
- Tests that asserted a removed tag now assert its absence where that matters (for example the Approve card, Home lots, New Lot order); tests about behaviour (approval gating, which settings changed, step states) keep asserting the behaviour by other means (values, accessible names, button states), not by deleting the check.
- `npm test`, `npm run eval:offline`, the web build and the full browser suite pass.
