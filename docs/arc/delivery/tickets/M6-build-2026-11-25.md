# M6 build order, from 2026-11-25

Om chose to build the full approved redesign now (session of 2026-11-25). This file fixes the order and the split of the M6 tickets in `M6-arc-ui.md` across frontend agents. The tickets, their acceptance criteria and the rules at the top of `M6-arc-ui.md` are unchanged.

## Order
1. **Shell** (`arc/ARC-M6-02-shell`): ARC-M6-01 token check, the app frame (sidebar, top bar, Arc launcher, hash routes, one file per page under `web/src/pages/`), the shared components in `web/src/components/m/`, and ARC-M6-02 (the Arc panel wired to `/api/arc/session` and `/api/arc/turns`). Every page group starts from this branch once it merges.
2. **Page groups, in parallel**, one branch and one agent each. A group only edits its own page files, its own components folder (`web/src/pages/<group>/` if it needs more than one file) and its own tests. Changes to shared components go back to the shell owner as a request.

3. **QA** per group by a separate qa-lead agent against the ticket criteria, one fix round by the group's builder, a re-check, then a `--no-ff` merge into `arc/main`.
4. **Gate**: the M6 review gate (`reviews/M6-review.md`) before any release.

## Rules every group follows
- No figure from a design PNG or HTML is hard-coded. Numbers come from an API response, or the element shows the designed "not connected" state that names what is missing.
- Where the backend does not exist yet (lists U1 to U14 in `00-plan.md` section 6.2), the element is built as designed and shows "not connected". Nothing is shown as working before its backend ticket passes.
- Pass-level wording is retired (`data/stale-claims.md`).
- Om's copy rule: the word "synthetic" is never shown; "Modelled on our plant" is used where the design says "Synthetic demonstration". Each such change is listed in the group's report.
- Approval stays human: a checkbox plus an Approve button, labelled as a simulated demo-session approval.
- Every group runs `npm run build` in `web/`, its Playwright tests, and screenshots of each screen in both themes at 1440x900 against the live project through `npm run live:local` on its own port, then compares them with the PNGs by eye.
