# UI audit: clutter, jargon and boxes to cut

Date: 26 Nov 2026. Branch: `claude/dazzling-clarke-17lvor`, cut from `arc/main` at `9d9a548`.

This is a list, not a change. Nothing below has been removed or restyled. The only edits on this branch are the wording changes in section 1. Every item has an ID so it can be accepted or rejected one by one.

How it was measured: each route of `/app/` was opened at 1440 px in the offline local backend, full-page screenshots were taken, and the text on each screen was counted. Arc was switched off in that configuration, so the Arc panel shows its "not connected" state. The Operator page was seen only in its empty state. Mobile was not checked.

## 2. Wording left alone, and why (needs a founder decision)

These are the labels that still say "demo", "prototype" or "illustrative". They were not reworded because each one is a true statement about how the system runs today, and the project's own rules (CLAUDE.md section 3, the responsible-AI policy) require it.

| ID | Text | Why it stays |
|---|---|---|
| D-1 | "Demo session, simulated", "Supervisor session, Demo access only.", "Approved in a demo session", "Supervisor, demo session" (Approve card, receipt, Operator, Prep Flow, sidebar) | The backend runs in `HACKATHON_DEMO` authorization. There is no named supervisor. Dropping the word would make the approval record read as a real sign-off. This changes when real sign-in ships, not before. |
| D-2 | "Prototype data, not live" (top bar, every page) | The data is modelled. Section 3 of CLAUDE.md: modelled is not measured. |
| D-3 | "Illustrative line, not a live view" and "Illustrative, no live readings." (Plant Explorer), "Illustrative animation" (Insights), "Illustrative line" (Home) | The 3D scenes are drawings, not the customer's line. |
| D-4 | "Working prototype" and the whole Planning roadmap | See PL-1. |
| D-5 | "Sample" chips on Delivery timeline and Throughput (Insights) | Those cards show placeholder shapes. |
| D-6 | Order intake accepts only the five approved files | The server returns `ORDER_SAMPLE_REQUIRED: "Arc confirms and plans approved sample orders only."` for any other file, including through the Upload a file button. The label now says "approved orders", but a customer's own purchase order is still refused. This is a product limit, not a wording one. |

Recommendation: keep D-1 to D-6 for the finals. A judge or a plant owner who finds a "supervisor approval" that is a simulated session will trust nothing else on the page. If the founders want them softened, the honest route is a shorter label, not a missing one.
