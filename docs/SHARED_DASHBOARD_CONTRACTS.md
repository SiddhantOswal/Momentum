# Shared dashboard integration contracts

This table compares the incoming `../public/js/api.js` / `app.js` assumptions with the existing authoritative contracts. The sole dashboard at `/` (`/dashboard` and `/dasboard` redirect here) uses the existing `src/ui/workflow.js`, `api.js`, `contracts.js`, currency and auth integration directly. There is no second transport or browser-side job coordinator.

| Capability | Incoming mismatch or risk | Integrated contract / behavior | Verification |
|---|---|---|---|
| Status | Treats HTTP 200 as downstream readiness | `GET /api/status`; reachability separate from service/model/persistence availability | Actual local HTTP + browser |
| Authentication | No supervisor/session integration | Existing Firebase or server-signed participant session flow, same-origin cookies/headers; no credentials copied into the dashboard | Existing auth suite + real local signed session and denial/gate checks |
| Extraction | Sends file alone; expects `spec`/`itemCode`; loses review references | `POST /orders/extract` multipart file + operator record/paper context; renders `purchaseOrderDocument`, `lines`, `orderProfile`, candidates, `reviewId`, `reviewFingerprint`; explicit source-line confirmation | Browser form-body, ambiguity, quantity and confirmation checks |
| Upload validation | Accepts PNG although backend permits PDF/JPEG | Existing byte/type/size boundaries; no PNG acceptance introduced | Preserved UI controls and existing server tests |
| Conditions | Expects flat values and invents source when absent | `GET /conditions/current?shift=DAY|NIGHT`; `data`, source, timestamp/age/staleness; confirmation remains explicit | Existing conditions/browser suite; shared controls unchanged |
| Machine inputs | Supplies unverified hardcoded plant standards | Seven existing schema-defined fields start empty; explicit planned-setting confirmation; edits invalidate confirmation/results | Browser + structural preservation |
| Risk | Flat `itemCode`/paper fields; missing confirmation; fills missing defect rates with zero | `POST /risk/predict` strict projected `order`, `conditions`, `conditionsConfirmed`, `levers`; genuine source and finite-response checks | Actual schema validation in browser harness; no zero fallback |
| Optimizer | Reuses flattened risk body and expects SQL rows | `POST /risk/optimize` full order/conditions, confirmation and seven levers; uses baseline/best/changes/savings response | Browser schema validation and returned-setting comparisons |
| Similar runs | `{itemCode, ambientRhPct}` and guesses response aliases | `POST /risk/similar-runs` `{order, conditions}`; actual `evidence` with source checks | Browser schema + returned records |
| Explanation | Sends `recommendedLevers` and formatted change rows | `POST /risk/explanation` `{order, conditions, prediction, optimization, evidence}`; presentation-only optimizer fields excluded by existing controller | Browser strict schema and prerequisite checks |
| What-if | Separate guessed request shape and stale-state risks | Shared risk projection; independent scenario; no approved-setting mutation; stale responses ignored | Delayed response/input-change browser test |
| Job preparation | Browser assembles an unsupported JobSheet payload and chooses final settings | `POST /jobs` original file, operator context, source-line references/confirmation, manual conditions/confirmation, seven levers and bound `Idempotency-Key`; server owns preparation | Multipart assertions; one creation request; persisted response feeds display |
| Execution | Frontend orchestration can repeat work during creation | Existing authenticated `/api/runs/{runId}/events`, real events only; no synthetic completion ticks | Actual-event fixture rendering; no second coordinator |
| Job review | Browser-made draft/choice can look authoritative | `GET /jobs/{id}` / durable creation response; full shared persisted review and source status; stages use stored recommended settings | Browser persisted draft and nine-stage table |
| Approval | Combines creation and approval; JSON `locale` preferences; infers status | Separate explicit confirmation dialog, `POST /jobs/{id}/approve?lang=en&currency=...`; stored DRAFT/status gates; server response authoritative | Browser confirms no call before confirmation; 409 remains failure; real local model gate refuses approval |
| PDF | Direct URL may omit protected auth headers; unpersisted fallback | Existing authenticated `GET /jobs/{id}/card.pdf` blob retrieval; separate local supplied-sheet utility remains labelled and cannot approve jobs | Browser PDF link after approval; existing PDF suite |
| Actual feedback | Sends unsupported `actualScrapKg` / `mainDefect`; claims completed-lot learning | Existing `POST /jobs/{id}/feedback` with matching `jobId`, supplied defect rates/photo and optional notes; no kg-to-rate inference or learning claim added | Browser `FeedbackInputSchema` check; existing feedback suite |
| Defect history | Guesses SQL-row aliases and count fallbacks | `POST /evidence/seen-before` `{defect, ambientRhPct}`; exact counts/groups/notes, safe text rendering | Browser payload and HTML-escaping checks |
| Photos | Incoming UI says no classification service | Existing `GET /evidence/approved-photos` and `POST /evidence/classify-photo` with only `{photoId}`; ten approved IDs, no arbitrary upload/storage added | Browser supported request and classifier result; existing real service tests |
| Impact | Separate iframe, duplicate source/rendering logic | Same-origin `GET /impact/summary`, existing source/authorization policy, privacy-safe item groups, accessible charts/tables; malformed reload clears old charts | Browser chart, provenance, currency and malformed-state checks |
| Currency | Missing-date fallback to “latest”; undated approximation | Existing `GET /fx?base=...`, dated/source-labelled display-only conversions; stored money unchanged | Browser dated conversion; existing FX suite |
| Mock mode | `?mock=1` imports bundled mock data | No incoming mock transport shipped or served; query does not change response authorization or enable model/service mocks | Browser no-model-call check; HTTP `/js/mock.js` and `/ui/mock.js` return 404 |

Server endpoint, validation, approval, privacy, model and provider-budget rules are unchanged. Actual service-success browser cases use explicit test fixtures, not production mock mode. Current model-evidence and provider-allowance limits still prevent claiming a new live cloud order-to-approved-card acceptance run.
