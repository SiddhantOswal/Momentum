## Availability and unresolved product acceptance

Default local execution is offline, with cloud adapters disabled. Success render tests inject fixtures only in the test browser and block external traffic. No application mock adapter is introduced.

The repository's later `OM_DECISIONS.md` resolves the prototype optimizer baseline to supervisor plan (D2); this rebuild follows returned results and makes no optimizer change. The original Blueprint baseline/threshold is a historical conflict with a written prototype resolution, not permission to change server gates. `config/model-acceptance.json` still reports blocked: aggregate R² meets Om's prototype thresholds, but complete sample-count/evaluation provenance is absent. Strength and Crack remain below the Blueprint's 0.6 target. Real PO1 operator-confirmed settings have not been fabricated. Photo classification has no route. Feedback-to-lot learning remains outside the existing feedback schema. Live persistence, approval, identity and current end-to-end acceptance require separately authorized verification.

`GET /insights/summary?from=&to=` remains available in the backend as before; it had no operator UI entry point to preserve. It is not silently represented as `/impact/summary`. Legacy `/api/agents/*` routes are intentionally not wired into the frontend.
